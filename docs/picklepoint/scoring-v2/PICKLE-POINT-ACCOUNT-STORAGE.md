# Account-backed history

New play starts with the existing LeewayPB sign-in. Pickle Point's D1 account_libraries table stores one authenticated library snapshot, independently of PaddleLog; Supabase remains authentication only. Server GET/PUT /api/library verifies the current bearer at the fixed provider /auth/v1/user endpoint, rejects anonymous/cookie-only/foreign-origin callers, scopes every prepared query to that verified subject and uses one conditional insert/update per write. Request-supplied emails/IDs never authorize access. No shared auth or PaddleLog configuration changes.

IndexedDB remains local-first for offline scoring. Source IDs, both revision lanes, game journals/players, explicit usage, and existing v1 outbox persist in the account snapshot. SDK tokens and photo/display caches do not. PUT uses expected cloud version; identical lost-response payload digest is acknowledged without duplicate mutation. A clean device pulls a newer cloud snapshot; dirty conflicting devices require explicit whole-library replacement review, with downloadable copies and a device-local recovery record. New source edits during an in-flight restore are protected by local CAS.

Unsigned legacy history is preserved in main and explicitly moved into an empty account library. It is not automatically attached to whoever signs in. Returning signed-in users can score offline; new devices need online sign-in/restore. Sync runs in the foreground when the app is open/online; check Account saved before switching devices. Cloud capacity is below 1.8 MB UTF-8 per snapshot. Local oversize/history remains exportable. Automatic cross-device merging, cloud collection backup restore UI and cloud deletion tombstones are not included. Use exported backups and conflict review for recovery.

D1 schema is generated with Drizzle (db/schema.ts, drizzle/0000_previous_layla_miller.sql); publishing provisions Pickle Point's logical DB binding and applies only its new bounded schema migration. No production seeds are inserted. Server assets retain existing account callback routes and no-store/no-referrer headers. Existing SDK-owned browser token persistence stays unchanged; no service-role key is introduced.
