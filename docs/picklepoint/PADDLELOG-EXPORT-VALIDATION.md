# Exporter validation and limits

Implemented in `src/paddlelog-export.js`, persisted by `src/storage.js`, surfaced in Settings by `dist/app.js`. Only Pickle Point was changed.

## Automated evidence

- Full existing suite plus first 9 exporter tests: **85/85 passed** (`npm test`). This includes engine recovery/scoring, offline shell, storage conflicts, voice flows and the DOM export preview/download flow.
- Final targeted exporter and DOM suite: **12/12 passed**, including 2 added tests for private email-like labels and fixture/producer compatibility.
- Large export test: 3,000 sessions with multibyte labels, multiple independently valid files, each strictly below 2,000,000 UTF-8 bytes; no missing or duplicated IDs. Oversized single sessions are skipped with a count.
- Persistence: unchanged repeat exports/reopen/backup round-trip preserve identity and revision; boundary, stored timezone and paddle-label edits increase export revision; notes and opponent-name edits do not.
- Usage: single and multiple paddles, explicit pauses/gaps, midnight crossings, timezone range changes, missing/empty intervals; no fabricated play time. Invalid/open/overlapping/zero-length intervals and unfinished records are skipped.
- Privacy: foreign/missing owners excluded; private fields and physical paddle IDs absent; email-like paddle labels excluded. Unknown additional fields are not copied.
- Fixtures are generated by `node scripts/export-fixtures.mjs` and checked against current producer output and schema envelope constants. Schema was reviewed structurally; no third-party JSON Schema validator is installed in this environment.

## Known limitations

- Existing owner-private single-library architecture only: no account-bound data isolation or shared-browser account switching. `local-owner` is not an authentication identity. Do not enable multi-user access without account-scoped storage.
- There is no existing restore UI. Backup identity/metadata round-trip is tested. An old restored backup or divergent restored copies can rewind/collide revisions; importer must reject lower revisions and surface equal-revision/content conflicts.
- Notes/context are deliberately omitted for privacy. Arbitrary personal information in paddle nicknames cannot be detected reliably; labels are listed for user review, and obvious email-like labels are rejected.
- Current tracking only records explicitly selected paddles while playing/unpaused. Missing intervals do not prove zero play. Elapsed-only records require PaddleLog confirmation before wear.
- Corrupt libraries that cannot pass the app’s existing recovery validation remain in the existing backup/recovery screen. This feature does not bypass or replace that protection; the standalone exporter validates and skips individual eligible records it receives.
- Physical iOS/Android downloads and native share sheets were not tested here. DOM tests verify preview and JSON Blob creation; Web Share is capability-detected with per-file download fallback. No real browser visual QA was available.
- PaddleLog itself, authentication, infrastructure and payments were not changed. Import support is separate. No automatic sync, wear assignment or deletion is performed.
