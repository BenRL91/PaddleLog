# Catalog workflow

Account catalogs remain in the existing state payload. No SQL schema migration or rewrite of physical paddles. Imported entries now optionally contain numeric thickness in mm; identity is normalized brand + model + shape + thickness. Existing unspecified variants remain valid. New variant-specific model IDs are computed on future paddle saves; historical stored IDs are not rewritten. Catalog is not an official certification database.

Search in Add/Edit paddle matches brand/model/shape/thickness tokens and lists up to 200 matching variants. Apply fills identification fields only (brand/model/shape/thickness), with confirmation before replacing nonblank conflicting values. Static weight, speeds, swingweight, twistweight, notes, photos and maintenance stay as entered. Shape/thickness must be checked against the user's actual unit. Manual entry remains always available and can be focused with My paddle isn't listed. Existing brand/model dropdowns remain for compatibility.

Matching references uses exact variants. A generic catalog entry with unspecified thickness can remain associated with matching model/shape measurements; a conflicting known thickness is never substituted. Ambiguous matches return no reference. Source kind/name/date and attributed specs display separately from unit measurements. These are imported source claims, not independently verified PaddleLog data. Manufacturer/reviewer/other provenance is preserved; no data was scraped or fabricated.

Import supports CSV (brand,model,shape,thickness) and JSON (plus reference metadata). Leading BOMs, quoted CSV cells and case-normalized identities are supported. Exact duplicate rows collapse; conflicting duplicate metadata for the same variant is rejected. User previews new/update/unchanged counts and up to 100 variant details; all rows are covered in the summary. Nothing is written until Save catalog changes. Failed save retains preview for retry. Cancel discards the preview. Import merges, retains existing fields omitted from incoming rows, and does not add/edit paddles. Concurrent conflicting changes to an imported variant fail with a review/retry message. JSON export/restore preserves variants and sources.

Tests cover variant identity/ambiguity, thickness validation, BOM CSV, duplicate/conflict rejection, source escaping, measurement isolation, selection consent, preview cancellation, failed-save retry, double Save, backup roundtrip and stale catalog conflicts, plus the existing full regression suite. Browser/iPhone visual QA remains necessary. Data coverage, licensed partner feeds, multiple reference sources per variant and approved photos remain future work.
