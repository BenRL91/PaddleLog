# Weight setup and comparisons

Physical paddle configuration now optionally contains `weights: {base, items}`. Existing top/side/butt/undergrip notes are preserved. No SQL migration or rewrite of existing records. Server preserves weights when an older client omits the nested field. JSON backup validation includes the new schema. Drafts store the full editor state in a hidden field and recover partial invalid entries without discarding them.

Each weight item has an ID, zone (top/sides/butt), type (tape/slider/cap/coin/other), label, added grams, longitudinal distance from butt (cm), and absolute lateral distance from centerline (cm). Positive added mass only: replacement caps require net additional mass compared with the original; lighter replacement parts are not modeled in this release. Grouped symmetric side pieces use their combined mass and common distance. Location labels do not silently change numeric placement.

Point-mass calculations: total mass = baseline grams + sum of added grams; balance = sum of mass × longitudinal position divided by total mass; swingweight delta = sum of kg × (longitudinal cm − 10)^2; twistweight delta = sum of kg × lateral cm^2. Baselines are explicitly before all listed additions. Missing baseline leaves total/balance unavailable. Estimates do not mutate measured specs or establish verified measurements. Configuration fingerprint includes entries, invalidating previous exact-configuration attestations after a placement change.

Pro comparisons are authorized through the existing account-bound entitlement refresh and support paddle specs, usage (including estimates), subjective feel, setup and individual source-reference differences. Missing numbers remain missing, never zero. Archived paddles stay selectable. No provider-specific purchase checks are introduced. Billing feature `comparisons` is now available; actual purchases remain disabled until external setup.

Catalog JSON can include `reference` with `kind` (manufacturer/reviewer/other), `name`, optional http(s) `url`, `asOf` date and `values`. Supported values: staticWeight (oz), length/width (in), thickness (mm), swingWeight/twistWeight (kg·cm²), serveSpeed/volleySpeed (mph). Template available in Settings. Reference values never fill or overwrite user measurements. Reference provenance is user-supplied, not independently verified. No manufacturer/reviewer data has been fabricated or scraped. Feed synchronization, multiple references per model, variant-specific catalog identity, and aggregate charts remain future work.

Tests cover known point-mass examples, pivot behavior, absent baseline, malformed mass/duplicate IDs, import/source validation, backup roundtrip, changed configuration fingerprint, slider/editor behavior, partial draft recovery, comparison gating, and old-client persistence. Real iPhone visual/gesture QA remains necessary.
